# **Sister Site Brief — Brand Carryover \+ SEO/AEO Rules**

Paste this into your prompt (or attach it) when building the new site for the same company.

---

## **1\. Brand Carryover (KEEP these)**

**Fonts**

* Primary typeface: **Inter** (weights 400, 500, 600, 700, 800), loaded from Google Fonts with preconnect to fonts.googleapis.com and fonts.gstatic.com, display=swap.  
* Font stack: 'Inter', \-apple-system, BlinkMacSystemFont, 'Segoe UI', Roboto, Helvetica, Arial, sans-serif.  
* Headlines: bold (700–800), tight tracking. Body: 400–500.

**Gold (keep exactly)** The gold system is a 4-step ramp, not a single color:

* \#f4be45 — core brand gold (accents, rings, icon strokes)  
* \#f6c95f — mid gold (most common usage: highlights, borders)  
* \#f6d479 — light gold (gradient midpoints)  
* \#ffe79c — pale gold (gradient highlights, glow text)  
* Supporting: \#fff0a3 / \#fff7c6 (brightest sparkle), \#b97618 (deep gold shadow), \#1a1407 (near-black gold-tinted dark)  
* Gold headlines use gradient text (dark gold → light gold → pale gold) with a subtle glow, e.g. shadow rgba(244,190,69,0.15).

**Vibe & tone (keep)**

* Premium, confident, medically credible — "advanced energy medicine" positioning. Authoritative but warm; never hypey or salesy in body copy (superlatives live in headlines only).  
* Copy voice: plain-language explanations of clinical concepts, specifics over adjectives (numbers, specs, warranty terms, FDA status), transparent pricing language.  
* Visual language: glassmorphism panels (bg-white/\[0.03\], backdrop-blur-xl, border-white/\[0.08\], large soft shadows), generous border radius (\~1rem base, up to 2.25rem on feature panels), soft glows behind key elements, scroll-reveal animations, trust-badge rows (FDA / warranty / financing icons).  
* **iOS caveat:** never nest a backdrop-blur element inside another backdrop-blur parent — it renders as bright solid blocks on iOS Safari. One blur layer max per stack.

**CHANGE these**

* Background & non-gold palette. Current site uses a near-black navy (hsl(220 50% 4%)) with blue hsl(217 91% 60%) primary and red hsl(350 89% 60%) secondary. Pick a **new background and new primary/secondary colors** for the sister site — the gold ramp above must stay and must still contrast well against whatever background you choose (gold reads best on dark or deep-toned backgrounds; if going light, use the deeper golds \#f4be45/\#b97618 for text and reserve pale golds for fills).

## **2\. SEO / AEO Rules (non-negotiable)**

**Per-page basics**

* Every page gets a unique \<title\> (≤60 chars, primary keyword first) and unique \<meta name="description"\> (140–160 chars, includes the answer to the page's core question).  
* One \<h1\> per page containing the primary keyword; logical h2/h3 hierarchy that mirrors how a person would ask questions.  
* Canonical URL tag on every page pointing to the production domain (absolute URL, no trailing query strings).  
* Open Graph \+ Twitter Card tags per page (og:title, og:description, og:image with absolute URL, twitter:card=summary\_large\_image).

**Structured data (JSON-LD) — this is the AEO backbone** Emit \<script type="application/ld+json"\> blocks per page, each with a stable unique id:

* **Organization** (site-wide): name, url, logo (absolute URL).  
* **Product** on every product/pricing page: name, description, image, offers with @type: Offer, numeric price, priceCurrency, availability (schema.org URL), and page url.  
* **FAQPage** on any page with an FAQ section: mainEntity array of Question/acceptedAnswer generated from the *same data* that renders the visible FAQ (never let the schema and the on-page text drift apart).  
* **MedicalWebPage** (or WebPage if not medical) with lastReviewed date and reviewedBy Person (name, credentials as honorificSuffix, jobTitle) — named human reviewer on every page builds E-E-A-T and answer-engine trust.  
* **BreadcrumbList** on nested pages.  
* Validate all JSON-LD (Google Rich Results Test / schema.org validator) before shipping.

**AEO (answer-engine) writing rules**

* Every FAQ answer must be self-contained: restate the entity by full name ("The Ultimate DOD Cardio MedBed costs…") so it works when quoted out of context by an AI answer engine.  
* Lead sections with a direct 1–2 sentence answer, then elaborate — answer-first structure.  
* Use exact, consistent canonical product names everywhere (page copy, schema, titles). One name per product, no synonyms drifting between pages.  
* Include concrete numbers (prices, specs, warranty lengths, session counts) in crawlable text, not only in images.

**If the site becomes multilingual**

* Structured data, brand names, product names, and prices stay **in English** — never machine-translate JSON-LD, titles used in schema, or canonical product names.  
* Use hreflang alternates and keep the default/canonical version English.

**Technical**

* robots.txt allowing crawl \+ pointing to sitemap.xml; sitemap lists every indexable page with absolute production URLs.  
* All images have descriptive alt text; hero/OG images served as absolute production URLs.  
* Preconnect to font origins; lazy-load below-the-fold images; keep Core Web Vitals healthy (no layout shift from late-loading fonts — use display=swap).  
* SPA note: if client-rendered, inject/cleanup JSON-LD and meta per route on navigation so each route carries its own head data.
